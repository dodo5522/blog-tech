## 完了済み

### 1. Node.js / pnpm バージョン指定の整理

- `package.json` の `packageManager` は `pnpm@10.18.0`
- `package.json` の `engines.node` は `24.13.1`
- `.github/workflows/ci.yml` の Node.js は `24.13.1`
- `.github/workflows/deploy.yml` の Node.js は `24.13.1`
- CI / deploy workflow の pnpm は `10.18.0`

### 2. formatter 対象の調整

- `.prettierignore` に `docs` を追加
- `.prettierignore` に `pnpm-lock.yaml` を追加
- 今後 `pnpm format` / `pnpm format:check` では `docs/` と `pnpm-lock.yaml` は対象外になる
- 既存コミット `2155f71` には、対応前に formatter がかかった `pnpm-lock.yaml` の差分も含まれている

### 3. 実施済み検証

- `pnpm format:check`

上記は成功済みです。

ローカル環境の Node.js が `v24.10.0` のため、`engines.node: 24.13.1` に対する pnpm warning は表示されます。CI は Node.js `24.13.1` を使うため、この warning はローカル環境差分として扱います。

### 4. Sanity fallback の公開制御修正

- `getPublishedPosts` は Sanity クエリが成功して空配列を返した場合、fallback 記事を返さないように修正
- `getTags` も同じ基準に揃え、Sanity クエリ成功時の空配列を尊重するように修正
- `getPostBySlug` は Sanity クエリ成功時に該当記事がない場合、fallback 記事へ差し替えないように修正
- fallback コンテンツは Sanity 未設定または fetch 失敗時だけ使う
- レビュー指摘の「空 dataset でサンプル記事が公開される」問題に対応済み

### 5. 未タグ記事の build 失敗対策

- GROQ の post projection で `tags` を `coalesce(tags[]->..., [])` に変更
- API 側でも `tags: post.tags ?? []` に正規化
- `getPostsByTagSlug` や記事カード表示で、未タグ記事が原因の `post.tags.some(...)` / `post.tags.length` 例外を起こさないように修正
- レビュー指摘の「公開記事に tags がない場合に tag page 生成で build が落ちる」問題に対応済み

追加検証:

- `pnpm format:check`
- `pnpm lint`
- `pnpm build`
