# 2026-04-20 Progress

## 概要

2026-04-20 時点で、MVP の骨組みは実装済みです。Astro の静的サイト、Sanity Studio スキーマ、GitHub Actions、Terraform の雛形、および関連ドキュメントの初回整備まで完了しています。

このドキュメントは、次に作業する人やエージェントが、何が終わっていて何が未完了かを即座に把握するための現時点のステアリングメモです。

---

## 完了済み

### 1. プロジェクト骨組み

- Astro プロジェクトの基本構成を追加
- TypeScript / ESLint / Prettier の最小構成を追加
- `.gitignore` を更新し、`node_modules`、`.astro`、`dist` などを除外
- `pnpm` ベースのスクリプトを定義

### 2. コンテンツモデル

- Sanity の `post`、`tag`、`author`、`siteSettings` を実装
- 補助オブジェクトとして `codeBlock`、`imageWithAlt`、`socialLink` を実装
- Portable Text ベースの本文構造を前提にスキーマを定義

### 3. Astro と Sanity の連携

- `@sanity/client` によるビルド時取得層を追加
- 公開済みコンテンツのみ取得する GROQ クエリを実装
- Sanity 未接続時でもローカル確認できるフォールバックコンテンツを実装
- Portable Text を HTML に変換して表示する描画処理を追加

### 4. 公開ページの実装

- `/`
- `/blog/`
- `/blog/[slug]/`
- `/tags/`
- `/tags/[slug]/`
- `/about/`
- `/404.html`

上記のルーティングと基本 UI を実装済みです。

### 5. SEO / RSS / Sitemap

- `BaseLayout` で title / description / canonical / OGP / Twitter Card を出力
- `rss.xml` を実装
- `robots.txt` を実装
- `@astrojs/sitemap` により `sitemap-index.xml` を生成する構成を追加

### 6. デプロイパイプラインの雛形

- GitHub Actions の CI workflow を追加
- GitHub Actions の deploy workflow を追加
- S3 sync + CloudFront invalidation を行う Terraform 雛形を追加
- GitHub OIDC 前提の IAM role 雛形を追加

### 7. 運用・開発ドキュメント

- `CONTRIBUTING.md` を追加
- `README.md`、`docs/ARCHITECTURE.md`、`docs/CONTENT_MODEL.md`、`docs/DEPLOYMENT.md`、`docs/OPERATIONS.md`、`docs/RELEASE_CHECKLIST.md` を更新
- `docs/DECISIONS.md` に GitHub Flow と merge commit 方針を追記

### 8. 実施済み検証

- `pnpm install`
- `pnpm lint`
- `pnpm format:check`
- `pnpm build`
- `pnpm exec sanity schema validate`

上記は 2026-04-20 時点で通過済みです。

## 未完了 / 残件

### A. Sanity 実運用接続

- 実際の `SANITY_PROJECT_ID` / dataset / token を投入して接続確認する
- Studio 上で初期コンテンツを作成する
- 公開済み記事、タグ、著者、サイト設定の実データで画面確認する

### B. デプロイの本番接続

- AWS 実リソースを Terraform で適用する
- GitHub Actions の `vars` / `secrets` を設定する
- `AWS_DEPLOY_ROLE_ARN`、`S3_BUCKET_NAME`、`CLOUDFRONT_DISTRIBUTION_ID` を実値に置き換える
- 本番 deploy workflow の実行確認を行う

### C. Sanity webhook の接続

- publish / unpublish を契機に GitHub Actions を起動する仕組みを実配線する
- `repository_dispatch` をどう発火させるかを確定する
- webhook 失敗時の再送・監視方法を運用文書に具体化する

### D. 404 / CDN 挙動の実機確認

- CloudFront 配下で SPA 的ではない静的配信の 404 応答が意図通りか確認する
- カスタムエラーレスポンスと `404.html` の見え方を確認する

### E. コンテンツ品質と UI の polish

- 実記事データでコードブロック、画像、本文余白を確認する
- OGP 画像の実データ運用を確認する
- fallback コンテンツに依存しない状態へ移行する

### F. ドキュメント具体化

- `docs/DEPLOYMENT.md` に実運用のロールバック手順を追記する
- `docs/OPERATIONS.md` に webhook 実運用時の確認手順を追記する
- `README.md` に初回セットアップ手順をもう少し具体化する
