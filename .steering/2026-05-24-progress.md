# 2026-05-24 Progress

## 概要

GitHub Actions の deploy ワークフローを site / studio で分離し、Studio 側は Terraform state の output を参照してデプロイ先を解決する方式に切り替えた。  
あわせて、運用ドキュメントに `terraform apply` の責務と実行タイミングを追記した。

---

## 完了した項目

### Deploy ワークフローの分離

- `deploy.yml` を `deploy-site.yml` へリネーム
- `deploy-studio.yml` を新規作成
- `concurrency` を site / studio で分離
  - site: `site-deploy`
  - studio: `studio-deploy`
- `push` トリガーに `paths` 条件を追加し、不要実行を抑制

### Studio デプロイの Terraform output 参照化

- `deploy-studio.yml` に `hashicorp/setup-terraform@v3` を追加
- `terraform -chdir=infra init`（backend-config 指定）を実行
- `terraform -chdir=infra output -raw` で以下を取得し、`GITHUB_ENV` へ受け渡す構成へ変更
  - `studio_bucket_name`
  - `studio_cloudfront_distribution_id`
- Studio 側の S3 sync / CloudFront invalidation は上記取得値を使用

### ドキュメント / 設定例更新

- `README.md`
- `docs/DEPLOYMENT.md`
- `docs/OPERATIONS.md`
- `env.example`

主な更新点:

- Studio deploy は `STUDIO_*` 変数ではなく `TF_STATE_BUCKET_NAME` / `TF_STATE_KEY` / `TF_STATE_REGION` を利用
- `deploy-studio.yml` が `terraform apply` を実行しないことを明記
- 初回および `infra/` 変更時に、先に `terraform apply` を実施する運用手順を追加
