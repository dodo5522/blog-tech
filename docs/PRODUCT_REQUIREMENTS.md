# PRODUCT_REQUIREMENTS.md

## 1. プロダクト概要

以下の構成で、個人向け技術ブログを構築する。

- フロントエンド: **Astro**
- CMS: **Sanity**
- 配信: **AWS S3 + CloudFront**

本ブログは、高速・低コスト・SEO 対応・保守しやすさを重視する。

---

## 2. 目的

- 技術記事を快適に公開・閲覧できること
- インフラを単純に保ち、運用コストを抑えること
- 独自バックエンド DB を持たないこと
- CMS によってコンテンツを管理できること
- コンテンツ更新後に自動リリースできること
- コンテンツ管理と公開配信を明確に分離すること

---

## 3. 利用者

### 3.1 公開閲覧者
公開済みの記事を閲覧する。

### 3.2 管理者
サイト全体設定、スキーマ管理、公開フロー管理を行う。

### 3.3 投稿者 / 編集者
Sanity 上で記事を作成・編集する。利用可能な権限は採用プランに依存する。

---

## 4. 機能要件

### 4.1 公開サイト
- ホームページ
- 記事一覧ページ
- 記事詳細ページ
- タグページまたはタグ絞り込み
- About ページ
- 404 ページ
- RSS フィード
- Sitemap
- robots.txt

### 4.2 記事コンテンツ
各記事は最低限以下を持つこと。

- title
- slug
- excerpt
- body
- cover image
- publishedAt
- updatedAt
- tags
- seoTitle
- seoDescription
- ogImage

### 4.3 CMS
- Sanity Studio で記事を管理できる
- タグを管理できる
- 著者を管理できる
- サイト設定を管理できる
- draft / published を扱える

### 4.4 デプロイ
- Sanity の公開済みコンテンツからサイトをビルドできる
- 静的ファイルを S3 に配置できる
- CloudFront 経由で配信できる
- CI または Sanity webhook を契機にデプロイできる

---

## 5. 非機能要件

- 公開サイトは静的ホスティングのみ
- 公開サイトのための実行時 DB は持たない
- 低コストで運用できる
- SEO の基本を満たす
- 高速に表示される
- 運用が単純
- シークレット露出を避ける
- ローカル開発が簡単である

---

## 6. MVP では対象外

- コメント機能
- 閲覧者アカウント
- 独自バックエンド API
- 高度な検索バックエンド
- 多言語対応
- 複雑な分析基盤
- ブラウザ上でのコンテンツ編集

---

## 7. 受け入れ条件

以下をすべて満たしたら MVP 完了とする。

- 公開済み記事が静的ページとして生成される
- 下書きが本番ビルドに含まれない
- S3 + CloudFront にデプロイできる
- SEO の基本要件が実装されている
- ドキュメントを見ればローカル起動とデプロイができる
- Sanity Studio でコンテンツ管理できる
