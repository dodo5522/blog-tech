# Build Ledger UI Redesign

## Purpose

公開サイト全体を、技術者向けの暗色UI「Build Ledger」へ再設計する。開発者らしい外観を第一にしつつ、備忘録として後から手順を再現できる読みやすさを優先する。個人ブログとしての個性は、情報構造を損なわない範囲で表現する。

Astroによる静的生成、Sanityによるコンテンツ管理、S3とCloudFrontによる配信、既存URL構造は変更しない。

## Scope

対象はホーム、記事一覧、記事詳細、タグ一覧・詳細、About、404、共通ヘッダーとフッターである。CSS、Astroレイアウト、表示コンポーネントを中心に変更する。

Sanityスキーマへの必須項目追加、コンテンツ編集機能、検索バックエンド、実行時API、認証、SSRは対象外とする。

## Visual Direction

### Concept

端末のログと実験ノートを組み合わせた「Build Ledger」を採用する。端末風の表現は一覧、メタ情報、コード、手順の構造化に限定し、長文本文には通常の日本語サンセリフを使う。

記憶に残る要素は、記事内の手順を「目的、コマンド、確認結果」の順に追える視覚階層である。装飾目的の番号やログ記号は使わず、記事番号、手順、時系列など意味がある場合だけ使用する。

### Color Tokens

- `ledger-bg`: `#101315` — ページ背景
- `ledger-surface`: `#171A1C` — 本文と主要コンテンツ面
- `ledger-surface-raised`: `#1D2124` — コード見出しなどの浮き上がり面
- `ledger-text`: `#E7E2DA` — 本文と主要見出し
- `ledger-muted`: `#9DA3A6` — 日付、読了時間、補助説明
- `ledger-copper`: `#D0A675` — リンク、現在位置、コードブロック上端、フォーカス

銅色は強調用途に限定する。状態は色だけで伝えず、下線、輪郭、ラベルなどを併用する。通常テキストと背景のコントラストはWCAG AA相当を満たす。

### Typography

- サイト名、セクション見出し、日付、タグ、コード関連情報にはシステム等幅フォントを使う。
- 記事本文と説明文には、日本語を読みやすいシステムサンセリフを使う。
- 本文幅は最大約70字を目安に制限する。
- 外部Webフォントへの実行時依存は追加しない。将来導入する場合はライセンスを確認した自己配信とする。

### Shape and Motion

カードを箱で囲みすぎず、細い罫線、余白、インデントで階層を表現する。角丸と影はコードブロックや浮き上がり面など、境界が必要な箇所に限定する。

ホバーは罫線色と短い位置移動に留める。`prefers-reduced-motion: reduce` では不要な動きを停止する。

## Page Layouts

### Global Header and Footer

ヘッダーはサイト名と `Blog`、`Tags`、`About` の主要リンクを常時表示する。端末プロンプトを思わせる表記を使えるが、リンク名は一般的な語彙を維持する。フッターはRSSとサイトマップへの導線を残す。

モバイルでは1列に畳み、ナビゲーションを隠さない。横幅不足によるページ全体の横スクロールを発生させない。

### Home

ページ上部に短いサイト宣言を置き、その下に新着記事をログ形式で縦に並べる。各項目の順序は日付、タグ、読了時間、タイトル、概要とする。

現行の右サイドバーは廃止し、タグを記事一覧上部のコンパクトな索引として配置する。主要な閲覧領域を広く保つ。

### Blog and Tag Listings

ホームと同じ記事項目構造を再利用する。記事カードごとの大きな面や影は使わず、横罫線と余白で区切る。項目全体をリンクにする場合も、タグなど内部リンクとの操作競合を避ける。

記事が0件の場合は、空であることと次に取れる行動を簡潔に表示し、グリッドや罫線を不自然に残さない。

### Article Detail

デスクトップでは、左に記事メタ情報、中央に本文、右に見出し目次を置く3列構成を基本とする。本文列を最大約70字幅に保ち、左右列は視覚的に抑える。

目次は既存のPortable Text見出しからビルド時に生成する。見出しアンカーも静的HTMLとして出力し、実行時JavaScriptを必要としない。見出しが少ない短い記事では目次を表示しない。

モバイルでは1列にし、目次を記事冒頭の開閉式要素として配置する。JavaScriptなしで操作できるHTML要素を優先する。

### About and 404

共通グリッドとタイポグラフィを使用する。404ではエラーコード、状況、ホームまたは記事一覧への導線を明確にする。別テーマの装飾は導入しない。

## Technical Content Presentation

コードブロックはファイル名、言語、コード本文を明確に分ける。長い行はブロック内で横スクロールさせ、ページ幅を壊さない。表と長いURLも局所的にスクロールまたは折り返しを適用する。

既存Sanityスキーマに専用の手順ブロックを追加しない。通常見出し、本文、リスト、コードブロックの組み合わせを、CSSによって「目的、コマンド、確認結果」と追いやすくする。コンテンツに意味のあるラベルが存在しない場合、UI側で内容を推測して付与しない。

読了時間は既存のビルド時算出を継続する。現行モデルには安定した記事番号がないため、今回の記事一覧には番号を表示しない。公開順から毎回変化する番号も採用しない。

## Components and Data Flow

- `BaseLayout` はSEOメタデータと共通外枠を維持する。
- `SiteHeader` と `SiteFooter` は共通ナビゲーションを担当する。
- `PostCard` はホーム、記事一覧、タグ詳細で使うログ形式の記事項目へ改修する。
- `TagPill` は小型の索引リンクとして再設計する。
- `PortableText` は見出しアンカー、コード、表、引用など本文表現を担当する。
- 記事目次のため、Portable Textの解析を共通のビルド時ユーティリティへ分離し、本文レンダリングと同じ見出し識別規則を使う。見出しが2件以上ある記事だけ目次を表示する。

Sanityから取得した公開済みコンテンツをAstroビルド時に変換し、静的HTMLとして出力する既存フローは変えない。クライアント側からSanityへ接続しない。

## Error and Fallback Behavior

Sanity未接続時のフォールバックコンテンツ、下書き除外、存在しない記事の404動作を維持する。記事、タグ、著者、画像、目次の一部が欠けてもレイアウトが成立するようにする。

画像がない場合に装飾用プレースホルダーを自動表示しない。テキスト主体の構成として自然に縮退させる。

## Accessibility

- キーボードフォーカスを銅色と明るい輪郭で明示する。
- 見出し順序、ランドマーク、ナビゲーションラベルを維持する。
- 色だけでリンクや選択状態を示さない。
- `prefers-reduced-motion` を尊重する。
- コード、表、長い文字列が200%ズームと狭い画面で全体レイアウトを壊さないようにする。
- タップ対象の間隔を確保し、モバイルでも主要ナビゲーションを常時利用可能にする。

## Validation

実装後に以下を確認する。

1. `pnpm lint` と `pnpm build` が成功する。
2. 既存のテストが成功する。
3. ホーム、記事一覧、記事詳細、タグ一覧・詳細、About、404をデスクトップとモバイル幅で目視確認する。
4. キーボードだけで主要リンク、タグ、目次、開閉要素を操作できる。
5. コードブロック、表、引用、画像、長いURLが本文幅を壊さない。
6. Sanity未接続時、記事0件、画像なし、短い記事でも不自然な空欄がない。
7. title、description、canonical、OGP、RSS、sitemap、robots.txtがUI変更後も維持される。
8. 静的出力にSanityトークンなどの秘密情報が含まれない。

## Non-goals

- コンテンツモデルの再設計
- Sanity StudioのUI変更
- クライアント側検索
- テーマ切り替え
- アニメーション中心の演出
- 外部フォント、アイコン、UIライブラリの追加
- 公開URLやデプロイ方式の変更
